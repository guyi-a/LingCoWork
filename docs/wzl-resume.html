方向一 · MCP 生态接入能力建设

  • MCP 客户端完整实现：为产品打通 MCP 开放生态，让用户能把内外部服务自助接入 Agent——从服务器配置管理、连接生命周期到远程工具动态注入完整落地；重点打磨远程服务的授权体验，自动探测服务器认证方式，用户点一次「授权」即走完 OAuth 全流程。
  • 连接层优化：把「让模型看见工具」和「真正建连」拆开——工具清单单独缓存，注入时不必连上 server；模型实际调用时才按需借连接。连接放进池子跨对话复用，空闲一段时间再回收，stdio 子进程不再每轮重启，远程工具首调和审批续跑都明显更快。

方向二 · 后台任务与技能生态

  • 长耗时任务异步化：为解决视频生成这类长耗时工具占住整轮对话、任务随应用重启而丢失的问题，将图片生成、视频生成等统一为后台任务：工具调用立刻返回，任务落库、独立调度，完成后主动通知对话接续；应用重启后按中断阶段恢复，视频凭远程任务 ID 续跑。对话不再被阻塞，任务不再丢失。
  • 公共 Skill 的发现与安装：为解决三方技能无从发现与安装的问题，接入 skills.sh 公共技能生态，打通搜索、预览、安装链路：模型在对话中按需检索生态、先读技能文档确认用途再安装，装好后与本地技能同等被发现。Agent 能力可按需自助扩展，不必再等人工引入。

方向三 · 浏览器使用能力建设

  • 独立浏览器路径：给 Agent 一套独立浏览器，没装扩展也能上网操作。基于开源 browser-use 落地，把首次安装拆成环境检测 / 本体安装 / 内核安装三步，进度实时反馈，本机已有 Chrome 则跳过内核下载；再打磨 Skill：定位为扩展未就绪时的兜底，登录、验证码交还用户，模型不在独立窗口里空转。
  • 用户浏览器桥接：让 Agent 直接操作用户日常用的浏览器——正在看的那一页、登录态、已开标签都在，内网站点不必再登一次。负责客户端 WebSocket 端点开发：承接扩展接入、把工具调用下发到当前窗口；打磨 Skill：先探测扩展状态，就绪走桥、未就绪自动回退独立路径，不擅自关闭用户已开的标签。

LingCoWork 个人项目 · Go · React · Electron
github.com/guyi-a/LingCoWork
基于 CloudWeGo eino ADK 自建的本地 Agent 工作站，在模型之上实现完整执行系统：多 Agent 拓扑、工具调用、分级审批、状态恢复与上下文压缩，覆盖文件处理、命令执行、资料检索、浏览器操作及代码修改、验证与审阅等真实工作区任务。Go 服务端、React 前端与 Electron 桌面端由一人实现。
  • 多 Agent 架构设计：采用 Supervisor + AgentAsTool 拓扑，将招聘搜索、简历分析、模拟出题等垂直能力按需委派给领域 Agent，并由只读 Explore 负责大范围代码探索；各子 Agent 使用独立上下文与提示词，执行事件实时回传并关联父级工具卡，避免领域知识和探索过程持续占用主 Agent 上下文。
  • 流式对话与分级审批：SSE 以服务端缓冲为权威源，断网、刷新都能重连续读、不丢内容。审批判定不依据工具名，而依据工具声明的调用后果（读写、破坏性、外联），未识别的调用默认转人工确认、不被静默放行；不可逆操作即使在全放行模式下也必须确认。中断状态持久化，重启后待审批任务仍能从断点继续。
  • 个性化与记忆：为解决常用指令反复重打、用户与项目偏好无法跨对话延续的问题——用户级自定义指令在对话框快捷选取、与输入内容拼装成完整指令一次发出；用户与项目两级记忆分别沉淀个人偏好与工作区约定，新对话自动携带。高频操作一键直达，Agent 越用越懂用户。
  • 长对话上下文压缩：为解决多轮长任务撑爆模型上下文的问题，压缩不删除任何历史消息，只生成一条结构化摘要——涵盖用户意图、任务进展、待办计划、技术要点与下一步交接；发给模型的上下文以摘要替换较早的历史、界面上照常显示完整历史；摘要滚动衔接前次压缩，多轮压缩不断层。长对话无限续跑，历史零丢失。
